# Manifest CLI — Tracker

Open work for the Manifest CLI repo, as one flat list.

- **This file is the canonical open-work register for the CLI repo** (locked 2026-08-15). Audits produce *evidence and verdicts*; the work they imply is filed here under a stable `§X.Y` ID. No audit maintains its own parallel to-do list: an audit's remediation section points back here, and its `FINDINGS.tsv` carries the owning §-ID in its `remediation` column. **Audit artifacts are deliberately untracked** (`CODEX_AUDIT_*` is gitignored, locked 2026-08-16) — they are local evidence for the run that produced them, and each locks a baseline of the tracked tree that committing its own output would invalidate. So this file is the only durable record: if a finding is not filed here, a fresh clone has no trace of it.
- Every item names a concrete deliverable and an anchor; the `§X.Y` label is a stable ID (referenced from commits, memory, audit findings, and the Cloud/workspace trackers — do not renumber).
- Drift policy: when an item ships, **delete it** from this file. Provenance lives in the merge commit and release history. A *fixed* defect is not an item; the item is whatever guard keeps it from returning. **Before deleting, re-file anything the entry names that has not shipped** — a shipped entry can carry unshipped obligations (a sweep it called for, a decision it deferred, a guard it left to a follow-up), and deleting it whole is how the §9.15 sweep vanished for a day (added 2026-08-17 after that).
- Status tag (2026-05-22 enterprise-readiness triage):
  - **T1** — release-blocking; absence allows lost user state, lost git history, or unrecoverable partial fleet state.
  - **T2** — contract integrity; absence allows the safe-by-default contract to drift or bypass.
  - **T3** — coverage, audit, or docs required before declaring the v1 enterprise release done.
  - **DEFER** — real value, but absence causes no safety harm at fleet-of-dozens scale.
  - **CUT** — considered and rejected; kept here so it doesn't reappear by accident. File a fresh item rather than reviving a cut entry verbatim if the reasoning changes.

- **§9.10 Ship failure report offers `git reset --hard` when no commit was ever created — it destroys uncommitted work.** [T1 — allows lost user state]
  - **Observed 2026-08-16**, real incident during the v59.1.0 ship. The pre-commit hook blocked `version_commit`; the failure report then printed `Roll back: git reset --hard 93fe4ac…`. Running it would have discarded every uncommitted change in the working tree — the 215-assertion `refute` conversion, the upstream-tracking fix, and the KEY MATERIAL / `manifest_gitignore_upgrade` work. **Nothing would have been recoverable**: none of it was committed, so there is no reflog entry, no stash, no dangling object to recover from.
  - **Why the advice is wrong here.** It is written for a failure *after* the version commit, where `HEAD` has moved and the tree holds only ship-generated files — there, resetting to `start_sha` correctly unwinds the release. On a **pre**-commit failure `HEAD` is still `start_sha`, so the reset unwinds *no* history and its only effect is to erase the working tree. The advice is not merely unhelpful in this case; it is the single most destructive command available, offered at the moment it does the most harm.
  - **Mechanism (verified 2026-08-16).** The emission guard at [`manifest-orchestrator.sh:130`](../modules/workflow/manifest-orchestrator.sh#L130) suppresses the line only when `push_status == success` **and** the failed step is post-push (`homebrew_*`, `github_release`, `completion_clean`). It has **no notion of whether a commit exists.** Our report read `failed step: version_commit`, `commits created: 0`, `tag: none`, `push status: not_attempted` — and printed the rollback regardless.
  - **Fix is cheap: the needed value is already computed.** `commits_created` is derived at [`:86-89`](../modules/workflow/manifest-orchestrator.sh#L86) and *printed to the user* at [`:96`](../modules/workflow/manifest-orchestrator.sh#L96), three lines above the emission. Gate the rollback line on `commits_created` being a positive integer. Fail safe on `unknown` (suppress, don't print) — an unverifiable count must not authorize a destructive command. When the count is 0, the correct advice is targeted, not global: revert only the ship-generated files (`VERSION`, `CHANGELOG.md`, `README.md`, `docs/INDEX.md`) via `git checkout HEAD -- …`, which is what actually recovered this incident.
  - **Guard to add with it:** a test asserting the report does **not** contain `reset --hard` when `commits_created` is 0. The existing coverage in [`tests/ship_resume.bats`](../tests/ship_resume.bats) exercises `emit_ship_failure_report` already, so the harness exists.
  - **Anchor:** [`modules/workflow/manifest-orchestrator.sh`](../modules/workflow/manifest-orchestrator.sh) (`emit_ship_failure_report`), [`modules/fleet/manifest-fleet.sh`](../modules/fleet/manifest-fleet.sh) (`:2671`, the divergent fleet copy). Related: §8.1a (the other mis-classified-recovery defect in this same function) and §9.15's duplicated-derivation half (the fleet copy of the classifier omits `completion_clean`, confirmed 2026-08-19, was `RED-001`). **All three are one statement — the report advises an action its own state data contradicts — so fix them together and behind a single shared classifier.**

- **§9.11 The release commit stages IDE/session state, and the guard that catches it is not installed on a fresh clone.** [T2 — contract integrity]
  - **Incident 2026-08-16.** The v59.1.0 ship was blocked at `version_commit` because `.claude/settings.json` carried absolute `/Users/<user>/…` paths. Claude Code writes "don't ask again" permission grants into that file *as you work* — it grew 19 → 24 rules during a single session, and one added rule (`WebFetch(domain:docs.claude.com)`) came from the very lookup used to diagnose this. Manifest's release commit is a bare `git add .` ([`manifest-git.sh:765`](../modules/git/manifest-git.sh#L765)), so every ship tries to commit whatever the IDE last wrote.
  - **Fixed in this repo only:** `.claude/settings.json` untracked 2026-08-16 (`git rm --cached` + the `!` negation dropped from `.gitignore`). It had been sanitized by hand once (`63a8ed5`, "free of absolute paths, usernames, and local toolchain locations") and re-polluted by three auto-commits since; 16 of 19 rules were one-off command strings, so it never functioned as curated team config.
  - **Still open — the template re-creates the exposure fleet-wide.** [`create_default_gitignore`](../modules/core/manifest-init.sh) re-includes `!.claude/settings.json` (manifest-init.sh:1101), so **every repo Manifest scaffolds** tracks the file Claude Code writes machine-specific paths into. Not changed unilaterally: whether teams want a shared Claude settings file is a policy call, not a bug fix. Decide it, then either drop the negation or pair it with something that keeps the file clean.
  - **The deeper defect.** `git add .` stages content nobody reviewed — the same root cause as §9.9 (key material) and adjacent to §9.10 (the recovery advice for its failures). The durable fix is at the CLI: the release commit should not stage IDE/session state, or should refuse to stage what the repo's own security hook would reject. That protects every repo Manifest ships rather than one `.gitignore` at a time.
  - **Distribution gap that makes it worse.** The pre-commit hook that caught this is reached via `core.hooksPath=.git-hooks`, which lives in `.git/config` — **not cloned**. [`CONTRIBUTING.md`](../CONTRIBUTING.md) documents it as manual per-clone setup, so on a fresh clone the guard is simply absent and a teammate can ship this contamination unblocked. Whatever fixes the above must not depend on the hook being installed.
  - **Unresolved, worth reporting upstream:** Claude Code's docs state that "don't ask again" rules save to `.claude/settings.local.json` (gitignored) and that **no setting redirects this** — yet the observed writes went to the tracked `settings.json` (extension build `anthropic.claude-code-2.1.233-darwin-arm64`; `settings.local.json` untouched across the same window). Documented and actual behavior disagree; do not build machinery that assumes either until it is understood.
  - **Anchor:** [`modules/git/manifest-git.sh`](../modules/git/manifest-git.sh) (`commit_changes`), [`modules/core/manifest-init.sh`](../modules/core/manifest-init.sh) (`create_default_gitignore`), [`.git-hooks/pre-commit`](../.git-hooks/pre-commit), [`.gitignore`](../.gitignore). Related: §9.9, §9.10.

- **§9.15 Sweep for "absent or malformed input treated as a value" — the shape four separate defects shared.** [T2 — contract integrity]
  - **Filed 2026-08-17, recovering work that was lost rather than found.** §9.12 and §9.13 each identified this as the common root of a run of defects, and each said so explicitly: *"worth a sweep for the shape rather than another one-off."* Both shipped in v59.2.0 and were deleted under the drift policy — which took the un-run sweep with them. The four instances are fixed; the hunt for the ones nobody has looked for was never performed and, until this entry, left no trace in the register. The drift policy above now carries the clause that should have prevented that.
  - **The four known instances**, every one confirmed by reproduction. (1) A missing `VERSION` read as the literal string `unknown`, then previewed as a releasable version — answering `-y` would have cut a release keyed on it (§9.12). (2) A malformed version coerced by shell arithmetic: `1.2.3-rc1` + `patch` silently became `1.2.4` (bash read `3-rc1` as `3 - rc1` with `rc1` unset), and 5-segment input produced a version *lower* than its input (§9.13). (3) 114 bats assertions written `! cmd` sitting mid-test, where bash exempts the command from errexit — they could not fail, and enforcing them exposed a real masked mismatch (§8.6b). (4) A ship failure report that prints `commits created: 0` and offers `git reset --hard` regardless (§9.10, still open — the only unfixed instance).
  - **Sweep output so far — seven further instances, each confirmed by reading the site (2026-08-19). The sweep is running; these are its results, not new leads.** (1) [`manifest-status.sh:1112`](../modules/core/manifest-status.sh#L1112) — `rev-list … || echo "0\t0"`, so a *failed* upstream comparison is parsed as ahead=0/behind=0 and reported as **"in sync"** immediately before a ship. The most dangerous instance found: it is a mutation-adjacent display path, exactly the case the verdict rule below says must refuse (was `TYPE-002`). (2) [`manifest-shared-functions.sh:289`](../modules/core/manifest-shared-functions.sh#L289) and [`:750`](../modules/core/manifest-shared-functions.sh#L750) — `case "${MANIFEST_CLI_OS:-Unknown}"` where `MANIFEST_CLI_OS` is **never assigned anywhere in `modules/`** (the module sets `MANIFEST_CLI_OS_OS`), so both OS branches are dead and the default always wins (was `PLAT-003`). (3) [`manifest-markdown-validation.sh:16-26`](../modules/docs/manifest-markdown-validation.sh#L16-L26) — `${#BASH_REMATCH[1]}` against a regex with **no capture group**: always 0, so the heading-level validator structurally cannot fail. Same class as §8.6b's 114 inert assertions, in product code rather than tests (was `RED-003`). (4) [`manifest-fleet-apply.sh`](../modules/fleet/manifest-fleet-apply.sh) (`_fleet_apply_plan`) — `A && B || C` returning failure when `A` is false. **Fixed 2026-08-19** (was `ATOM-004`; see §9.20). (5) the config lock's `_manifest_config_lock_acquire … || return 0` caller, where acquisition failure was reported as success — **fixed 2026-08-19 with the lock rework; skipping is still correct when a live holder exists, but it now says so instead of returning silently** (see §9.20). (6) [`tests/install_requirements.bats`](../tests/install_requirements.bats) — the namespace audit listed `docs/IMPROVEMENT_TRACKER.md`, deleted in an earlier rename; `grep … 2>/dev/null || true` swallowed the missing path, so the sweep silently scanned less than it claimed and still passed. **Fixed 2026-08-19** with an explicit existence guard, A/B-verified: fails with the dead path present, passes without. (7) [`scripts/manifest-cli-wrapper.sh`](../scripts/manifest-cli-wrapper.sh) sets `set -e` while [`scripts/manifest-cli.sh`](../scripts/manifest-cli.sh) sets `set -eo pipefail` — the **installed** entrypoint runs without `pipefail`, so the shell options differ by how the CLI was invoked. Not an absent-input case but the same root: a default nobody chose (was the salvageable half of `PLAT-009`).
  - **Second half of the shape: duplicated derivation.** §9.13 found **five** copies of one version calculation, agreeing only while every version had exactly three segments. Five copies is five chances to disagree, and the disagreement surfaced as a confidently wrong number rather than an error. A sweep that looks only for absent inputs misses this half, so both belong in one pass. **Confirmed instance of this half (2026-08-19, was `RED-001`): the ship-completion classifier exists twice and the copies disagree.** [`manifest-orchestrator.sh:130`](../modules/workflow/manifest-orchestrator.sh#L130) matches `^(homebrew_|github_release$|completion_clean$)`; the fleet copy at [`manifest-fleet.sh:2671`](../modules/fleet/manifest-fleet.sh#L2671) matches only `^(homebrew_|github_release)`. A fleet member whose push succeeded but which failed at `completion_clean` is therefore **not** classified `pushed-then-stranded` and is offered rollback advice for a release that is already public — the §9.10 defect, reachable only through the fleet path. Extract one shared classifier rather than correcting the copy. Also confirmed: `_json_escape` has two definitions where the nested one wins process-wide (§9.22), and the two entrypoints carry different shell options (instance 7 above).
  - **Deliverable — an enumeration with a verdict per site, not a blanket refactor.** Candidate classes to enumerate: fallback-to-literal (`:-unknown`, `|| echo unknown`, and any default that is a *string a caller could act on*); `2>/dev/null` on an **input redirection**, which silences the command's stderr but not the shell's failed redirect (§9.12's second defect — three raw `No such file or directory` lines escaped that way); `read -r a b c` into a fixed name list, where the last name absorbs the whole tail; and `$(( ))` over values read from a file or a user. Each site gets one of two verdicts — *legitimate default* (absence genuinely means "use this") or *must refuse* — and the must-refuse ones get a guard in the same change. **Sites, not a sweeping rule:** `unknown` is correct in read-only display paths and wrong on any path a mutation keys off, and only reading the site distinguishes them.
  - **No linter covers this**, which is why it is a sweep and not a gate. The one exception is instance (3): shellcheck's **SC2251** fires on exactly that shape and is already tracked as the missing hard gate in §8.6b — do not re-file it here. Expect this item's output to be new filed items plus their guards, then delete it.
  - **Anchor:** [`modules/core/manifest-shared-functions.sh`](../modules/core/manifest-shared-functions.sh) (`manifest_version_next` — the consolidated derivation the sweep should treat as the pattern to match), [`modules/core/manifest-ship.sh`](../modules/core/manifest-ship.sh) (`manifest_ship_require_version_file` — the pattern for a refusal), [`modules/workflow/manifest-orchestrator.sh`](../modules/workflow/manifest-orchestrator.sh) (`emit_ship_failure_report`). - **§9.20 The steady-prod fix campaign, and the reason it runs reproduce-first.** [T1 — in progress, resume here]

  - **The protocol, which earned its place three times over.** (1) Reproduce against the REAL entrypoint — `scripts/manifest-cli.sh`; there is no `bin/manifest`, and invoking one silently no-ops into `/dev/null`. (3) A/B every fix against `git stash` — a regression test that passes on unfixed code is decorative. (4) Beware the harness's own bugs: a `tr -d "]("` that left a `)`, a `set -o | grep '^pipefail *on'` that missed a tab, a zsh glob abort that skipped a cleanup and produced a false negative. Each of those first read as a product defect.

- **§9.2 Rate limiting for fleet `gh` loops (`init fleet` repo creation, topics, roster) + docs.**
